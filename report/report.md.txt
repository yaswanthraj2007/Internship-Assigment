==> 1. Objective

The objective of this project is to train a feedforward neural network from scratch (no TensorFlow/PyTorch/Keras) to classify all 35 character classes of upper-case letters A-Z and digits 1-9.

---------------------------------------------------------------------------------------------------------------------------------------
==> 2. Dataset Preparation

Since there was no existing dataset provided for this project, a synthetic dataset was generated by rendering all 35 character classes as images using multiple system fonts (Arial, Times New Roman, Courier, Verdana) with the PIL `ImageDraw` module to introduce natural variation (as people can write the same character with slightly differing strokes depending on the font they use). Each character class was generated with 60 images each (rotated by a random angle of +-15 degrees, and with light noise added to pixel values) for a total of 3560=2100 images - well above the minimum requirement of 50 samples per class.
For the actual training of the model, all images were rendered using a higher resolution (64x64 pixels) before being scaled down to a uniform 28x28 size (the standard character recognition convention) and normalized to pixel values in the [0, 1] range. The resulting 784-dimension vector for each image was then passed into the fully-connected neural network. Labels for classification were one-hot encoded into 35-dimensional vectors.

Finally, the dataset was split into a 70/15/15 ratio of train/validation/test using stratified sampling to maintain class distribution consistency across all subsets.

---------------------------------------------------------------------------------------------------------------------------------------
3. Neural Network Implementation

A fully-connected feedforward neural network was implemented with the following structure:


        ===> Input (784) -> Hidden Layer 1 (128, ReLU) -> Hidden Layer 2 (64, ReLU) -> Output (35, Softmax) <===


Weights were initialized using He initialization (normal distribution with mean 0 and std 2/fan_in) which preserves variance as data passes through ReLU layers.

During forward propagation, for each layer, the pre-activation component `z = a_prev @ W + b` is calculated, with ReLU (max(0, z)) used for the hidden layers and softmax (exponentiated and normalized probabilities) used for the output layer to obtain predicted class probabilities.

For loss computation, categorical cross-entropy loss with logits was used as the loss function, with predictions clipped to the [0, 1] range to avoid `log(0)` instability in computation:

                                            +---------------------------------+
											| L = -(1/N) Σ y_true log(y_pred) |
                                            +---------------------------------+

Gradient descent was performed using backpropagation through all layers of the network, calculating the derivative of the loss with respect to the weights using the chain rule. An important simplification used in practice is that when softmax and cross-entropy loss are combined, their derivative with respect to the output layer's pre-activation simplifies to `dz_output = y_pred - y_true`. This derivative is then used to calculate the gradient of the loss with respect to the weights of each layer, and weights are updated using basic mini-batch gradient descent:

                                               +------------------------+
                                               |W = W - learning_rate dW|
                                               +------------------------+

The training process was run for 100 epochs with a batch size of 32 and a learning rate of 0.1. Vanilla mini-batch gradient descent was used as opposed to more advanced optimizers like Adam, as they would not have been implemented from scratch.

During training, both the train and validation losses/accuracies were plotted to observe convergence. As expected, the loss decreased smoothly with no nan values during training, and both the training and validation accuracies eventually converged to 100%:

												+===================================+
												|       Metric        | Final Value |
												|---------------------|-------------|
												| Train Accuracy      | 100.0%      |
												| Validation Accuracy | 99.68%      |
												| Train Loss          | 0.0016      |
												| Validation Loss     | 0.0082      |
												+===================================+

See `images/training_curves.png` for the training progress.

The slight gap between the train (100%) and validation (99.68%) accuracy likely represents mild overfitting, and is due to the limited font variation (4 fonts) and augmentation (+-15 degrees rotation in training data) during dataset generation.

---------------------------------------------------------------------------------------------------------------------------------------
==> 4. Evaluation on Test Set

The model achieved 100% accuracy on the test set, with a loss of 0.0027. A confusion matrix was generated (see `images/confusion_matrix.png`) for the standard test set, confirming that no characters were misclassified on the standard test set (as expected, as the test set was generated using the same augmentation as the training set).

==> 5. Misclassification Analysis (Stress Test)

To evaluate whether the model actually learns to classify characters in a meaningful way, a second, much more aggressive stress test set was generated using rotation angles of +-35 degrees and noise of 0.10-0.25. Using this stress test set, the model correctly classified only 70% of characters, resulting in 105 misclassified out of 350 total. The sudden drop in performance from 100% (standard test) to 70% (stress test) demonstrates that the model generalizes poorly to inputs that are significantly different from what it was trained on.
For individual misclassification analysis, let us analyze the table below of the top 8 most common misclassifications (excluding the rows where the predicted class was the same as the true class):

+---------------------------------------------------------------+
| # | True | Predicted | Confidence (Wrong) | Confidence (True) |
|---|------|-----------|--------------------|-------------------|
| 1 |   A  |     4     |      96.06%        |       1.46%       |
| 2 |   A  |     V     |      65.01%        |       16.76%      |
| 3 |   A  |     4     |      87.82%        |       11.60%      |
| 4 |   A  |     4     |      93.64%        |       4.97%       |
| 5 |   A  |     V     |      84.47%        |       2.01%       |
| 6 |   A  |     4     |      86.82%        |       0.39%       |
| 7 |   A  |     6     |      49.29%        |       4.18%       |
| 8 |   B  |     S     |      81.89%        |       0.00%       |
+---------------------------------------------------------------+

Analysis of specific misclassifications:

1. A -> 4 (most frequent single confusion, 4 occurrences): At large rotation angles, the triangular peak and crossbar of "A" visually collapses into a shape similar to the diagonal stroke and crossbar of "4". Both characters share a similar stroke skeleton once rotated ~30°+, so the model - which learned spatial pixel patterns rather than true structural/topological features - confuses them.

2. A -> V: Heavy noise combined with rotation can erode the crossbar of "A" completely, leaving only the two diagonal strokes - which is structurally identical to "V". This suggests the model's decision boundary relies heavily on the presence of the crossbar, a fragile feature.

3. B -> S: At certain rotations, B's two stacked loops can distort into a shape similar to S's curves under added noise.

4. Most of the other common confusions (e.g., J->R, U->G, V->P, D->O, H->G, K->W) follow a similar pattern of characters that share curved or angular structural similarity.

Root cause summary:

	- Primary: distribution shift. The model was never exposed to rotations beyond +-15°, so inputs with rotation up to +-35° are out-of-distribution.
	- Secondary: limited robustness. A fully-connected network treats each pixel independently in its first layer, with no built-in translation/rotation invariance - unlike convolutional neural networks, which would generalize better to such spatial distortions.
	- High confidence in wrong predictions (many >80% in the table) shows the model is confident incorrectly - it hasn't learned to express uncertainty when inputs are unfamiliar, a known limitation of standard cross-entropy-trained classifiers.

---------------------------------------------------------------------------------------------------------------------------------------
==> 6. Conclusions & Limitations

Despite the limitations of the from-scratch NumPy implementation, the model successfully learns to classify all 35 character classes with 100% accuracy on the test set.
The gap between the training and validation set accuracy highlights the model's generalization boundary, and performance drops consistently as inputs are moved away from the training distribution - as can be seen in the stress test set with extreme rotations and added noise. A more robust model (with a wider range of rotations during training augmentation) would perform better on such inputs.
Possible improvements (not implemented as part of this from-scratch/NumPy project) include wider rotation range during training augmentation, dropout/regularization to reduce overfitting, and a convolutional neural network architecture for better spatial invariance.
